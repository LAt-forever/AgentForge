# 后端设计 + Agent 岗面试学习资料库设计

## 背景与目标

- **目标读者**：校招候选人，主攻后端开发 / Agent（AI 应用）工程方向。
- **核心目标**：建立一套可持续维护、可面试前快速突击的学习资料库，覆盖计算机基础、后端核心、Agent 与 AI、系统设计、面试实战、求职资源六大块。
- **存放位置**：当前 `vibe-agent` 仓库根目录下的独立文件夹 `面试资料/`，与业务代码解耦，但便于在开发之余随手补充。

## 设计决策

1. **一级目录按知识领域切分**：对齐校招面试的考察模块，便于按主题系统复习。
2. **中文文件夹名**：提升可读性，方便日常快速定位。
3. **每篇文档统一四层结构**：是什么 → 为什么 → 怎么做 → 面试怎么说，保证输出可直接用于面试表达。
4. **集中式编写规范**：`00-元信息/文档编写规范.md` 统一新增文档的落点、模板、命名规则，避免资料膨胀后失控。

## 每篇文档讲什么

每篇文档统一采用 **“是什么 → 为什么 → 怎么做 → 面试怎么说”** 四层结构：

| 模块 | 每篇核心内容 |
|---|---|
| 计算机基础 | 概念原理 + 高频考点 + 画图辅助记忆 + 一句话面试版答案 |
| 后端核心 | 技术原理 + 源码级关键点 + 生产踩坑 + 与竞品对比 |
| Agent 与 AI | 论文/框架原理 + 自己项目中的落地 + 岗位-specific 问题 |
| 系统设计 | 场景分析 → 估算 → 架构图 → 存储/接口/扩展 → 权衡 |
| 面试实战 | 题型 + 答题模板 + 自己的答案草稿 + 复盘记录 |
| 资源 | 可直接用的模板、不同公司侧重点、外部链接 |

## 新增文档/内容时放哪、怎么写

### 放置规则

| 新增内容 | 放置位置 |
|---|---|
| 新增一个知识点 | 按主题放入 `01-计算机基础/`、`02-后端核心/` 或 `03-Agent与AI/` 的对应子目录 |
| 新增一个可讲项目 | `02-后端核心/后端项目.md` 或 `03-Agent与AI/Agent项目.md` 中新增一节 |
| 新增一道系统设计题 | `04-系统设计/经典场景/` 下新建 `<场景名>.md` |
| 新增一类面试题型 | `05-面试实战/` 下新建文档，或在已有文档末尾追加 |
| 新增一家公司准备 | `06-资源/公司准备/` 下新建 `<公司名>.md` |
| 新增简历版本 | `06-资源/简历/版本/` 下新建 `<岗位方向>.md` |
| 新增术语 | `00-元信息/术语表.md` 中追加 |

### 文档模板

每篇新文档建议遵循以下模板：

```markdown
# 标题

## 一句话定义
<!-- 面试时能直接说的 1-2 句话 -->

## 核心原理
<!-- 概念、流程、关键组件 -->

## 为什么这样设计 / 优缺点
<!-- 面试常问的 trade-off -->

## 实际应用 / 项目经验
<!-- 结合自己做过的项目 -->

## 高频面试题
<!-- 3-5 道题 + 回答要点 -->

## 延伸链接
<!-- 论文、博客、源码 -->
```

### 命名与附件规则

- **文件/文件夹**：中文标题，不加序号（目录顺序由 README 维护）。
- **图片**：统一放 `assets/` 子目录，命名 `<文档名>-<序号>.png`。
- **代码片段**：统一放 `snippets/<文档名>/` 下。
- **链接收藏**：`06-资源/链接收藏.md` 按主题分组，避免变成无序列表。

## 实施计划概要

1. **搭建骨架**：创建 `面试资料/` 全部目录 + `README.md` + `00-元信息/` 下四个元文档。
2. **建立模板**：在 `文档编写规范.md` 中写入模板和命名规则；创建第一篇示例文档（如 `01-计算机基础/操作系统.md`）。
3. **分批填充**：按 `01 → 02 → 03 → 04 → 05 → 06` 的顺序逐篇补充，优先填充面试命中率高的模块。
4. **持续维护**：每次新增内容前先看 `文档编写规范.md`，确保格式一致；每月回顾 `README.md` 路线图，调整优先级。

## 范围与排除

- **包含**：面试知识点整理、答题模板、项目讲稿、系统设计题、简历模板、公司准备。
- **不包含**：完整的在线判题系统、自动化面试工具、与 `vibe-agent` 业务逻辑耦合的功能。
