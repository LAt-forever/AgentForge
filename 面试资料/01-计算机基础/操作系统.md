# 操作系统

## 一句话定义

操作系统是管理计算机硬件与软件资源、为应用程序提供统一接口的系统软件。

## 核心原理

### 进程与线程

- **进程**：资源分配的基本单位，拥有独立的地址空间。
- **线程**：CPU 调度的基本单位，共享进程的资源。
- **协程**：用户态轻量级线程，由程序自己调度，切换开销小。

### 内存管理

- **虚拟内存**：让每个进程认为自己拥有完整地址空间，通过页表映射到物理内存。
- **页表 / 页缺中断**：访问不在物理内存中的页时触发缺页中断，由 OS 加载数据。
- **TLB**：页表的高速缓存，加速虚拟地址到物理地址的转换。

### IO 模型

- **阻塞 IO**：调用一直等待数据就绪。
- **非阻塞 IO**：立即返回，需要轮询。
- **IO 多路复用**：select/poll/epoll，一个线程管理多个连接。
- **异步 IO**：内核完成 IO 后通知应用。

## 为什么这样设计 / 优缺点

- **进程隔离**：设计目标是保证系统稳定性——一个进程崩溃不会波及其他进程。代价是上下文切换需要保存/恢复大量状态（页表、寄存器等），开销较大。这是“稳定性优先”的取舍。
- **线程共享内存**：设计目标是降低同一任务内并发执行的通信成本——线程共享地址空间，数据传递无需拷贝。代价是需要引入锁、信号量等同步机制，否则会出现数据竞争。这是“效率优先、程序员承担复杂度”的取舍。
- **虚拟内存**：设计目标是同时解决三个问题：① 内存隔离（进程互不干扰）；② 超过物理内存的寻址（按需换页）；③ 简化程序链接/加载（统一地址空间）。代价是每次内存访问都需要页表转换，因此引入 TLB 作为硬件加速。这是“抽象换性能”的经典权衡。
- **多种 IO 模型并存**：设计目标是用尽可能少的系统资源服务尽可能多的连接。阻塞 IO 简单直接，但一个连接占一个线程；非阻塞 IO 解放了线程，但需要轮询浪费 CPU；IO 多路复用（epoll）用事件驱动兼顾高并发与低消耗；异步 IO 进一步将数据拷贝也交给内核，但编程模型复杂。这是“编程简单性 vs 系统吞吐量”的连续谱。
- **协程**：设计目标是在用户态实现高并发——避免内核线程切换的高成本，同时保持类似同步代码的写法。代价是协程阻塞时会卡住整个线程，需要搭配非阻塞 IO 和事件循环。这是“把调度权从 OS 下放到运行时/程序员”的取舍。

## 实际应用 / 项目经验

- 在高并发服务中使用线程池 + IO 多路复用（如 Go 的 netpoll、Java NIO）。
- 使用协程（Go goroutine）降低高并发场景下的切换成本。

## 高频面试题

1. **进程和线程的区别？**
   - 首先，进程是资源分配的基本单位，拥有独立的地址空间、页表和文件描述符；线程是 CPU 调度的基本单位，共享所属进程的资源。
   - 其次，进程间通信需要 IPC（管道、消息队列、共享内存等），成本高；线程间共享内存，通信简单，但需要同步机制防止竞态。
   - 最后，进程切换开销大（需切换页表、刷新 TLB），线程切换只需保存寄存器，开销小得多。

2. **什么是虚拟内存？**
   - 首先，虚拟内存让每个进程拥有独立的、连续的虚拟地址空间，通过页表映射到物理内存，实现进程间的内存隔离。
   - 其次，它支持“按需分页”——只将当前需要的页加载到物理内存，其余放在磁盘，从而运行超过物理内存大小的程序。
   - 最后，TLB 作为页表的高速缓存，加速地址转换；缺页中断则负责在访问未加载页时从磁盘调入数据。

3. **select、poll、epoll 的区别？**
   - 首先，select 和 poll 都是线性扫描：每次调用都需要遍历所有监听的 fd，时间复杂度 O(n)，且 select 有 fd 数量上限（1024/2048）。
   - 其次，epoll 基于事件通知和内核中的红黑树 + 就绪链表，只有活跃的 fd 才会返回，时间复杂度 O(活跃数)，无 fd 上限。
   - 最后，epoll 支持边缘触发（ET）和水平触发（LT），在高并发场景（如 Nginx、Redis）下性能显著优于 select/poll。

4. **进程间通信方式有哪些？**
   - 管道（Pipe）：半双工，父子进程间通信，最简单但受限。
   - 消息队列（Message Queue）：内核维护的消息链表，支持双向，但涉及内核态拷贝。
   - 共享内存（Shared Memory）：最快的 IPC，直接映射同一块物理内存，但需要信号量等同步机制配合。
   - 信号量（Semaphore）：用于进程/线程间的同步与互斥，不传输数据。
   - 套接字（Socket）：最灵活，可跨网络，本地也可使用 Unix Domain Socket 减少协议栈开销。
