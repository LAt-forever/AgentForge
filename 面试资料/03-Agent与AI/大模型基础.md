# 大模型基础

## 一句话定义

大模型（Large Language Model, LLM）是基于 Transformer 架构、在海量文本数据上通过自监督学习预训练得到的超大规模神经网络，具备强大的语言理解、生成和推理能力，是构建 AI Agent 的"大脑"。

## 核心原理

### 1. Transformer 架构

Transformer 是 2017 年 Google 在论文《Attention Is All You Need》中提出的架构，彻底改变了 NLP 领域。

**核心组件：**

- **自注意力机制（Self-Attention）**：让模型在处理每个 token 时，能够同时关注输入序列中的所有位置，计算它们之间的相关性权重。公式为：
  ```
  Attention(Q, K, V) = softmax(QK^T / sqrt(d_k)) * V
  ```
  其中 Q（Query）、K（Key）、V（Value）分别由输入向量经过不同的线性变换得到。

- **多头注意力（Multi-Head Attention）**：将注意力机制并行执行多次（如 12、16、32 头），每个头学习不同的关注模式，最后拼接并线性变换，增强模型的表达能力。

- **位置编码（Positional Encoding）**：由于自注意力本身不包含序列顺序信息，通过正弦/余弦函数或学习得到的位置编码，将位置信息注入到输入嵌入中。

- **前馈网络（Feed-Forward Network）**：每个注意力层后接一个全连接前馈网络，对特征进行非线性变换。

- **层归一化与残差连接**：Layer Normalization + Residual Connection，帮助深层网络稳定训练。

**编码器-解码器结构：**

- **Encoder**：双向注意力，适合理解任务（如 BERT）
- **Decoder**：因果/单向注意力（Masked Self-Attention），适合生成任务（如 GPT 系列）
- **Encoder-Decoder**：适合序列到序列任务（如 T5、BART）

### 2. 预训练（Pre-training）

预训练是在大规模无标注语料上通过自监督任务学习通用语言表示的过程。

**主流预训练目标：**

- **自回归语言建模（Autoregressive LM）**：给定前文预测下一个 token，如 GPT 系列。目标函数为最大化序列的条件概率：
  ```
  L = -sum(log P(x_i | x_<i))
  ```

- **掩码语言建模（Masked LM）**：随机掩码部分 token，让模型预测被掩码的内容，如 BERT。

- **前缀语言建模（Prefix LM）**：结合自回归和掩码，如 T5 的 span corruption。

**预训练数据：**

- 网页文本（Common Crawl）、书籍（BooksCorpus）、代码（GitHub）、百科（Wikipedia）、对话数据等
- 数据清洗：去重、过滤低质量内容、去除 PII（个人身份信息）
- 数据配比：不同来源数据按一定比例混合，代码数据通常能提升推理能力

**Scaling Laws（缩放定律）：**

OpenAI 和 DeepMind 的研究表明，模型性能（Loss）与三个因素呈幂律关系：

- 模型参数量（N）
- 训练数据量（D）
- 计算量（C = 6ND，FLOPs）

即：在资源充足时，增大模型、增大数据、增加计算都能持续提升性能。

### 3. 微调（Fine-tuning）

微调是在预训练模型的基础上，使用特定任务的标注数据进行进一步训练，使模型适应下游任务。

**全量微调（Full Fine-tuning）：**

- 更新所有参数
- 效果好但计算成本高，容易过拟合小数据集
- 需要大量 GPU 显存

**参数高效微调（PEFT）：**

- **LoRA（Low-Rank Adaptation）**：在原始权重矩阵旁引入低秩矩阵 A 和 B（r << d），只训练 A 和 B，冻结原权重。推理时 W' = W + BA。可将可训练参数减少到 0.1%~1%。
- **QLoRA**：LoRA + 4-bit 量化，进一步降低显存占用，可在单卡消费级 GPU 上微调 70B 模型。
- **Prefix Tuning / Prompt Tuning**：在输入前添加可学习的虚拟 token，只训练这些前缀嵌入。
- **Adapter**：在 Transformer 层之间插入小型适配器模块，只训练适配器参数。

**指令微调（Instruction Tuning）：**

- 使用（指令，输入，输出）三元组格式的大规模数据集进行微调
- 让模型学会遵循人类指令，从"补全文本"转变为"执行任务"
- 代表工作：FLAN、Alpaca、ChatGPT 的 SFT 阶段

### 4. Prompt Engineering（提示工程）

Prompt Engineering 是通过设计和优化输入提示（Prompt），引导大模型产生期望输出的技术，无需修改模型参数。

**核心技巧：**

- **Zero-shot**：直接给出任务描述，模型凭借预训练知识完成
- **Few-shot**：在 prompt 中提供 1-10 个示例（in-context learning），引导模型模仿输出格式和风格
- **Chain-of-Thought（CoT）**：在示例中展示推理过程（"Let's think step by step"），显著提升数学和逻辑推理能力
- **Zero-shot CoT**：在问题后加 "Let's think step by step"，无需示例也能激发推理
- **Self-Consistency**：对同一个问题采样多条推理路径，投票选出最一致的答案
- **Tree of Thoughts（ToT）**：将推理过程组织为树形结构，允许回溯和探索多条路径

**Prompt 设计原则：**

- 清晰明确：任务描述具体，避免歧义
- 结构化：使用分隔符（###、"""、XML 标签）区分不同部分
- 角色设定：让模型扮演特定角色（"你是一位资深算法工程师..."）
- 约束条件：明确输出格式、长度限制、风格要求
- 思维链：对复杂任务，要求模型先思考再回答

### 5. Token

Token 是大模型处理文本的最小单位，是模型输入和输出的基本单元。

**分词方式：**

- **BPE（Byte-Pair Encoding）**：从字符开始，迭代合并最频繁出现的字符对，如 GPT-2/3/4 使用
- **WordPiece**：类似 BPE，但基于语言模型概率选择合并，如 BERT 使用
- **SentencePiece**：基于 Unicode 的 BPE，不依赖空格分词，适合多语言，如 T5、LLaMA 使用
- **Unigram**：从大规模词表开始，逐步删除对损失影响最小的 token

**关键概念：**

- 1 个中文汉字通常编码为 1-2 个 token（GPT 系列中约 1.5 个 token/汉字）
- 1 个英文单词通常编码为 1 个 token（常见词）或拆分为多个 subword（罕见词）
- 上下文长度（Context Window）：模型能处理的最大 token 数，如 4K、8K、32K、128K、200K
- 输入 + 输出的总 token 数不能超过上下文长度

**Token 与成本：**

- 大模型 API 通常按输入和输出的 token 数量计费
- 上下文长度限制决定了模型能"记住"多少信息
- 长上下文技术（如 RoPE、ALiBi、NTK-aware scaling）让模型处理更长的文本

### 6. 幻觉（Hallucination）

幻觉是指大模型生成看似合理但实际错误、虚构或与事实不符的内容。

**幻觉类型：**

- **事实性幻觉**：编造不存在的事实、人物、事件、数据
- **忠实性幻觉**：与输入上下文或源材料不一致，如摘要偏离原文、问答答非所问

**幻觉产生原因：**

- **知识边界**：预训练数据有截止日期，模型对之后的事件一无所知
- **训练目标**：语言建模目标是生成"流畅"的文本，而非"正确"的文本
- **概率采样**：采样过程引入随机性，可能生成低概率的错误内容
- **上下文不足**：缺少相关上下文时，模型倾向于"猜测"而非"承认不知道"
- **训练数据噪声**：预训练语料本身包含错误信息

**缓解方法：**

- **RAG（检索增强生成）**：从外部知识库检索相关文档，作为上下文输入
- **事实核查（Fact-checking）**：生成后通过外部工具验证关键事实
- **知识编辑**：直接修改模型中的特定知识（如 ROME、MEND）
- **高置信度采样**：降低 temperature，使用 greedy decoding 减少随机性
- **训练阶段优化**：使用 RLHF 对齐人类偏好，惩罚幻觉输出
- **自我验证**：让模型检查自己的输出（"请验证上述回答是否正确"）

## 为什么这样设计 / 优缺点

**Transformer 相比 RNN/LSTM 的优势：**

- **并行计算**：自注意力可以并行处理整个序列，而 RNN 必须顺序计算，训练速度提升显著
- **长距离依赖**：注意力机制直接连接任意两个位置，有效捕获长距离依赖关系
- **可解释性**：注意力权重可以可视化，了解模型关注哪些 token
- **可扩展性**：架构简单统一，易于扩展到千亿甚至万亿参数

**Transformer 的局限：**

- **计算复杂度**：自注意力的计算复杂度为 O(n^2)，序列长度增加时计算量平方增长
- **内存消耗**：需要存储完整的注意力矩阵，长序列时显存占用巨大
- **位置信息弱**：相比 RNN 的隐式位置编码，Transformer 需要显式添加位置信息
- **数据饥渴**：需要海量数据才能发挥优势，小数据场景不如传统方法

**预训练 + 微调范式的优缺点：**

- 优点：预训练一次，微调多次复用；小数据也能获得好效果；通用知识迁移到特定任务
- 缺点：预训练成本极高（数百万美元级）；全量微调依然昂贵；存在灾难性遗忘风险

**Prompt Engineering 的优缺点：**

- 优点：零成本适配新任务；灵活快速；无需 GPU 资源
- 缺点：效果不稳定，对 prompt 措辞敏感；难以处理复杂任务；存在 token 浪费

## 实际应用 / 项目经验

**应用场景：**

- **文本生成**：文章写作、代码生成、邮件起草、营销文案
- **文本理解**：情感分析、意图识别、实体抽取、文本分类
- **问答系统**：客服机器人、知识问答、文档问答
- **翻译与摘要**：机器翻译、长文档摘要、会议记录提炼
- **推理与规划**：数学解题、逻辑推理、代码调试、任务规划

**面试可谈的项目切入点：**

- 参与过基于 LLM 的文本生成或理解项目
- 使用 LoRA/QLoRA 微调开源模型（如 LLaMA、ChatGLM）适配特定领域
- 设计过 Prompt 模板和 few-shot 示例库，提升业务场景效果
- 处理过 Token 长度限制问题，使用文本切分、滑动窗口、Map-Reduce 策略
- 解决过模型幻觉问题，引入 RAG 或后校验机制

## 高频面试题

**Q1: 为什么 Transformer 使用 LayerNorm 而不是 BatchNorm？**

- BatchNorm 对 batch 维度做归一化，在 NLP 中序列长度变化大，batch 统计不稳定
- LayerNorm 对每个样本独立归一化，不受 batch size 和序列长度影响
- Transformer 中不同位置的 token 需要独立处理，LayerNorm 更适合

**Q2: 自注意力机制的计算复杂度是多少？如何优化？**

- 标准自注意力复杂度为 O(n^2 * d)，其中 n 是序列长度，d 是维度
- 优化方法：
  - 稀疏注意力（Sparse Attention）：只计算局部或稀疏位置的注意力，如 Longformer、BigBird
  - 线性注意力（Linear Attention）：通过核技巧将复杂度降到 O(n * d)，如 Performer、Linformer
  - 分块注意力：将序列分块处理，如 FlashAttention（IO-aware，降低显存占用而非理论复杂度）
  - 状态空间模型（SSM）：如 Mamba，将复杂度降到 O(n)

**Q3: GPT 和 BERT 的主要区别是什么？**

- GPT 使用 Decoder-only 架构，单向（因果）注意力，自回归生成，适合文本生成任务
- BERT 使用 Encoder-only 架构，双向注意力，掩码语言模型预训练，适合理解任务
- GPT 系列：GPT-1/2/3/4、LLaMA、ChatGLM
- BERT 系列：BERT、RoBERTa、ALBERT、DeBERTa

**Q4: LoRA 的原理是什么？为什么有效？**

- 原理：假设权重更新 Delta_W 是低秩的，用两个低秩矩阵 BA 来近似，其中 B 是 d x r，A 是 r x k，r 远小于 d 和 k
- 只训练 A 和 B，冻结原权重 W，参数量从 d*k 降到 r*(d+k)
- 有效的原因：预训练权重已经包含了丰富的语义信息，微调只需要在特定方向上做小幅度调整，这些调整可以用低秩矩阵很好地近似

**Q5: 什么是 Temperature 和 Top-p 采样？**

- **Temperature**：控制概率分布的"尖锐程度"。T > 1 使分布更平坦，输出更随机、有创意；T < 1 使分布更尖锐，输出更确定、保守；T = 0 等价于贪婪解码
- **Top-p（Nucleus Sampling）**：从累积概率达到 p 的最小 token 集合中采样。动态调整候选集大小，避免 Top-k 在分布平坦时包含过多低概率 token，或在分布尖锐时遗漏合理候选
- 通常两者结合使用：temperature=0.7, top_p=0.9

**Q6: 大模型为什么会出现幻觉？如何缓解？**

- 原因：见"幻觉"部分
- 缓解：见"幻觉"部分
- 面试中可补充：幻觉是大模型固有的局限性，完全消除非常困难，实际应用中需要多管齐下

**Q7: In-Context Learning 为什么有效？**

- 大模型在预训练时从海量文本中学习了各种任务模式和格式
- Few-shot 示例激活了模型在预训练阶段学到的相关任务表示
- 示例提供了输出格式的"模板"，引导模型生成符合期望格式的回答
- 与梯度更新无关，纯粹通过注意力机制在推理时"读取"示例信息
