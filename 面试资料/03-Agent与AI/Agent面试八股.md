# Agent 面试八股

## 一句话定义

本文档汇总了 Agent 岗位校招面试中的高频技术问题及回答要点，涵盖 Agent 架构、RAG、多 Agent 协作、评估安全等核心领域，帮助候选人系统准备面试。

## 核心原理

以下按主题分类整理高频面试题，每题提供核心回答要点和延伸思路。

---

## 高频面试题

### Q1: 什么是 AI Agent？与单轮大模型问答有什么区别？

**回答要点：**

- AI Agent 是以大模型为"大脑"的自主智能体，具备感知、推理、行动、记忆的闭环能力
- 单轮问答是"一问一答"，Agent 是"多轮交互+工具调用+状态维护"
- Agent 可以调用外部工具（搜索、计算、API），单轮问答只能依赖模型内部知识
- Agent 有记忆系统，支持多轮对话和上下文延续，单轮问答每次独立
- Agent 可以做任务规划和分解，单轮问答直接生成答案
- 类比：单轮问答像"咨询顾问回答一个问题"，Agent 像"项目经理带领团队完成一个项目"

---

### Q2: 请详细解释 ReAct 范式的原理和流程。

**回答要点：**

- ReAct = Reasoning（推理）+ Acting（行动），由 Google 在 2022 年提出
- 核心思想：大模型交替进行"思考"和"行动"，而非一次性生成答案
- 标准循环：Thought（分析当前状态）-> Action（调用工具）-> Observation（获取结果）-> 重复
- 示例：回答"2024年诺奖得主是谁" -> Thought"需要搜索" -> Action"search()" -> Observation"韩江" -> Thought"已获得信息" -> Final Answer
- 优势：推理过程透明、每步有外部验证、减少幻觉、适合探索性任务
- 劣势：多步交互延迟高、早期错误会传播、简单任务过度设计

---

### Q3: RAG 的基本流程是什么？如何解决幻觉问题？

**回答要点：**

- 四阶段流程：索引（文档切分->向量化->存储）-> 检索（向量相似度召回）-> 重排（精排 Top-K）-> 生成（文档+查询->LLM 生成）
- 解决幻觉：
  - 事实锚定：将模型约束在检索到的真实文档范围内
  - 引用标注：要求模型标注信息来源，增强可验证性
  - 拒绝策略：信息不足时明确拒绝回答，而非编造
  - 后校验：生成后用外部工具或模型验证关键事实
  - 多文档交叉验证：多个来源一致时可信度更高
- RAG 的局限：检索失败必然导致生成错误；文档本身错误会被模型"忠实"复述

---

### Q4: 向量检索和关键词检索（BM25）各有什么优缺点？为什么要做混合检索？

**回答要点：**

- 向量检索（Dense Retrieval）：
  - 优点：捕获语义相似性，理解同义词、语义变体
  - 缺点：对专有名词、产品型号、精确匹配的召回效果差；计算资源要求高
- 关键词检索（BM25）：
  - 优点：对精确匹配效果好，计算简单高效，可解释性强
  - 缺点：无法理解语义，"电脑"和"计算机"被视为不同词
- 混合检索：两者互补，分别检索后使用 RRF（Reciprocal Rank Fusion）融合结果
- 实际效果：在大多数场景下，混合检索的 Recall 和 NDCG 显著优于单一方法

---

### Q5: 什么是文本嵌入（Embedding）？如何选择嵌入模型？

**回答要点：**

- Embedding 是将文本映射到高维向量空间的技术，语义相似的文本在向量空间中距离近
- 原理：使用预训练的语言模型（如 BERT）将文本编码为固定维度的向量（通常 768/1024/1536 维）
- 选择标准：
  - 关注 MTEB（Massive Text Embedding Benchmark）排行榜
  - 中文场景优先选择 BGE、GTE、E5 等中文优化模型
  - 领域适配：通用模型在特定领域（法律、医学）效果可能不如领域微调模型
  - 维度与效率权衡：高维模型效果好但存储和检索成本高
- 关键要求：文档嵌入和查询嵌入必须使用同一个模型，保证向量空间一致

---

### Q6: 大模型为什么会出现幻觉？除了 RAG 还有什么缓解方法？

**回答要点：**

- 幻觉原因：
  - 训练目标是最小化语言模型的困惑度（生成"流畅"文本），而非"正确"文本
  - 知识有截止日期，对之后的事件一无所知
  - 概率采样引入随机性，可能生成低概率错误内容
  - 缺少相关信息时，模型倾向于"猜测"而非"承认不知道"
- 缓解方法（除 RAG 外）：
  - 高置信度采样：降低 temperature，使用贪婪解码
  - 自我验证：让模型检查自己的输出（"请验证上述回答"）
  - 训练优化：RLHF 对齐人类偏好，惩罚幻觉输出
  - 知识编辑：直接修改模型中的特定知识（ROME、MEND）
  - 不确定性表达：训练模型在不确定时表达不确定性
- 关键认知：幻觉是大模型固有的局限性，完全消除非常困难，实际应用需要多管齐下

---

### Q7: 什么是 Function Calling / Tool Use？在 Agent 中如何实现？

**回答要点：**

- Function Calling 是让大模型输出结构化工具调用请求（JSON 格式）的能力
- 实现方式：
  - 在 API 请求中定义工具的 JSON Schema（名称、描述、参数类型）
  - LLM 根据用户输入判断是否需要工具，选择工具并生成参数
  - 外部系统执行工具，将结果（Observation）返回给 LLM
  - LLM 基于新信息继续推理或生成最终回答
- 另一种实现：ReAct 格式，LLM 输出 "Action: tool_name\nAction Input: params"，由解析器提取执行
- 工具可以是任何函数/API：搜索、计算、数据库查询、文件操作、第三方服务
- 关键挑战：工具选择的准确性、参数生成的正确性、工具错误的处理

---

### Q8: Agent 的记忆系统如何设计？短期记忆和长期记忆有什么区别？

**回答要点：**

- 短期记忆（Working Memory）：
  - 当前对话的上下文，受限于 LLM 的上下文窗口
  - 使用滑动窗口管理（保留最近 N 轮），超出部分进行摘要压缩
  - 支持多轮对话中的指代消解和话题延续
- 长期记忆（Long-term Memory）：
  - 跨会话的持久化记忆，存储在外部数据库中
  - 实现方式：
    - 向量记忆：对话历史编码为向量，存入向量数据库，语义检索召回
    - 结构化记忆：提取关键事实（用户偏好、项目信息），以键值对/知识图谱存储
    - 摘要记忆：对历史对话进行摘要，保留关键信息
- 记忆检索：用户输入时，检索最相关的历史片段，与当前上下文一起输入 LLM
- 代表工作：MemGPT（操作系统式内存管理）、MemoryBank（人类式记忆系统）

### Q9: 什么时候需要使用多 Agent 系统？与单 Agent 相比有什么优劣？

**回答要点：**

- 适合多 Agent 的场景：
  - 任务可明确分解为多个子任务，需要并行处理
  - 涉及多个领域知识，需要不同专家协作
  - 对系统鲁棒性要求高，不能单点故障
  - 需要多角度分析以避免单一模型的偏见
- 多 Agent 优势：专业化、并行化、鲁棒性、可扩展性、多样性
- 多 Agent 劣势：协调复杂度高、通信开销大、一致性问题、调试困难
- 单 Agent 优势：简单、延迟低、成本低、易于调试
- 判断标准：任务复杂度、领域广度、延迟要求、成本预算

---

### Q10: 什么是 RLHF？它的流程和优缺点是什么？

**回答要点：**

- RLHF = Reinforcement Learning from Human Feedback，从人类反馈中进行强化学习
- 三阶段流程：
  1. SFT（Supervised Fine-Tuning）：在指令数据上微调模型
  2. 奖励模型训练：收集人类对回答的偏好排序，训练模型预测人类偏好分数
  3. RL 优化：使用 PPO 算法，让策略模型生成能获得高奖励的回答
- 优点：能捕捉复杂的人类偏好，显著提升模型有用性和安全性
- 缺点：需要大量人工标注数据；训练不稳定（奖励黑客问题）；成本高；存在对齐税
- 替代方案：DPO（Direct Preference Optimization），无需奖励模型，直接用偏好数据优化

---

### Q11: 如何防止 Prompt 注入攻击？

**回答要点：**

- Prompt 注入：用户在输入中嵌入指令，试图覆盖系统预设的安全指令
- 常见攻击形式："忽略之前的指令"、角色扮演、编码绕过、分隔符注入
- 防御方法：
  - 输入与系统指令分离：使用 API 的不同字段，避免字符串拼接
  - 最小权限原则：Agent 只拥有完成任务所需的最小权限
  - 输出约束：限制输出格式，减少被注入后的操作空间
  - 输入过滤：检测已知的注入模式（规则+模型）
  - 多层验证：对敏感操作增加二次确认
  - 对抗训练：在训练数据中包含注入攻击样本，增强模型鲁棒性
- 关键认知：Prompt 注入是 LLM 应用的固有风险，完全防御非常困难，需要多层防护

### Q12: 请比较 LoRA 和全量微调的优缺点。

**回答要点：**

- 全量微调：
  - 更新所有模型参数
  - 优点：效果通常最好，能充分适配特定任务
  - 缺点：计算成本高（需要大量 GPU 显存）、容易过拟合小数据集、存在灾难性遗忘
- LoRA（Low-Rank Adaptation）：
  - 在原始权重旁引入低秩矩阵 BA，只训练 BA，冻结原权重
  - 优点：参数量减少 99%+、训练速度快、存储成本低（只需保存 BA）、可切换不同 LoRA 适配不同任务
  - 缺点：效果在某些任务上略逊于全量微调；秩 r 的选择需要调参
- 选择建议：大部分场景优先使用 LoRA/QLoRA，只有在效果不达标时才考虑全量微调
- QLoRA：LoRA + 4-bit 量化，进一步降低显存，可在单卡消费级 GPU 微调 70B 模型

## 为什么这样设计 / 优缺点

本八股文档采用"问题+要点"的结构设计，原因如下：

- **面试导向**：校招面试时间有限，面试官希望听到结构化的回答，而非冗长的叙述
- **要点优先**：每题列出 4-6 个核心要点，确保覆盖关键知识点，同时留有发挥空间
- **延伸提示**：部分题目提供延伸方向，帮助候选人展示深度思考
- **分类清晰**：按主题分类，便于针对性复习薄弱环节

## 实际应用 / 项目经验

**使用建议：**

- 不要死记硬背，理解每个要点背后的原理，用自己的话组织回答
- 结合自己的项目经验，在回答中穿插实际案例（"在我参与的 XX 项目中..."）
- 对于开放性问题，先给出核心定义，再展开解释，最后总结
- 如果遇到不会的问题，诚实承认，但可以展示相关知识的迁移能力（"这个问题我没深入研究过，但我了解相关的 XX 技术..."）

**面试回答技巧：**

- **STAR 法则**：Situation（背景）-> Task（任务）-> Action（行动）-> Result（结果）
- **结构化表达**：使用"首先...其次...最后..."、"从 X 方面来看..."等框架
- **量化成果**：尽量用数字说明效果（准确率提升 X%、延迟降低 Y ms）
- **展示思考过程**：对于复杂问题，可以先分析思路再给出答案，展示问题解决能力
